## Result

All four client bases have selectable HTTP adapters and an OpenAPI contract shared with the backend. Templates remain independent: they do not import server code or access SQL. The contract describes data and behavior without requiring Laravel; a custom implementation must comply and test conformance.

Exportable guides: [React](../../starters/web/api-integration.en-US.md), [HTML/CSS/JavaScript](../../starters/web-vanilla/api-integration.en-US.md), [Flutter](../../starters/flutter/api-integration.en-US.md), [Kotlin](../../starters/kotlin-android/api-integration.en-US.md), and [backend](../../starters/backend-php/api-integration.en-US.md).

The default client mode remains memory. An explicit URL enables HTTP; there is no silent fallback. The backend continues using its repository port and SQL adapter for SQLite, PostgreSQL, or MySQL.

## Example Decisions

The [neutral contract](../../starters/backend-php/contracts/task-api-v1.openapi.json) uses OpenAPI 3.1.0, revision `1.0.0-draft.1`. An identical copy is included in each starter, and a maintenance test detects drift. Titles were aligned at 80 code points. Flutter and PHP previously used 120, not 80 in every client as the initial document incorrectly stated: code, tests, and documentation were corrected. The reduction is incompatible with existing titles longer than 80; user data is not automatically migrated or truncated.

The server creates IDs and controls versions. Adapters retain observed versions, send conditional writes, and do not retry uncertain writes. Titles and local times generated by memory-mode services do not become remote authority: only the title is sent on creation. The API has no creation timestamp; web/Kotlin represent that value as unknown (`null`), not an invented date.

Explicit URL selection, response/pagination bounds, timeouts, redirect rejection, and DTO validation were implemented. Interfaces show some remote errors using the generic unconfirmed-operation notice and allow reloading. The React client retains a confirmed write even if the subsequent refresh fails.

The Android client performs networking off the main thread. Plain HTTP exceptions are limited to loopback/emulator in debug; remote destinations require HTTPS. CORS configuration enumerates exact origins and does not enable credentials; it does not replace authentication.

## Repeat the Isolated Integration

From the root, with Node and PHP available and backend dependencies installed:

```text
node scripts/test-api-integration.mjs
node scripts/test-api-integration.mjs --serve
```

The first form verifies contract copies, create/list/update/delete, cross-client persistence, conflicts, server IDs, unknown time, and CORS over real HTTP. It creates its own temporary SQLite database and loopback server and ignores the `.env` connection. It removes only its fixture on completion.

The second form retains that fixture and prints its URL for Flutter/Android/browser tests. Enter `stop` or send Ctrl+C for cleanup; there is a 30-minute limit. Each starter guide provides variables and commands. The fixture allows local origins 5173 and 5180. Do not use a consumer database as a fixture.

## Pending Outside This Local Evaluation

Authentication/authorization, production policies, remote TLS, cross-engine data migration, concurrent load, uncertain-write recovery, and idempotency require additional product decisions. macOS/iOS still require a Mac; native Linux and physical devices were not verified. Remote CI was not run, and no public application was deployed. Adapters do not resolve those limitations on their own.
